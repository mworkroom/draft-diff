# 2026-11-03 DraftDiff Development Log

## Work Summary

감수한 Before 문서 앞에는 장문 코멘트가 있지만 학생의 After 문서는 본문부터 시작해, 비교 화면의 시작 위치가 어긋나는 문제를 줄였다. 기본으로 Before 시작부터 `단락 앞 숫자는 기존 단락 순서입니다.`까지 제외하고 본문을 비교한다.

## Work Completed

- 영어 체크박스 `Skip opening comments in Before`를 추가하고 기본으로 켰다. 비교 후 설정을 바꾸면 선택된 파일로 바로 재비교한다.
- 원본 파일 대신 메모리의 DOCX 사본에서 해당 범위를 제거해 비교와 화면 표시 모두 본문부터 시작하도록 했다. 체크를 끄면 원래 파일로 전체 내용을 복원한다.
- Word 내부에서 문장이 여러 글자 서식·문단으로 나뉘거나 공백이 달라도 찾는다. 남은 본문의 글자·문단 속성과 뒤쪽 페이지 나눔은 보존하고, 시작부의 빈 문단·이전 페이지 나눔만 정리한다.
- 기준 문장이 없으면 전체 문서를 유지하고 안내한다. 제외 후 본문이 없으면 체크 해제를 안내한다. 렌더링 한쪽이 실패해도 양쪽 작업이 종료된 후 재시도를 허용한다.
- 공개용 가상 예제 Before에도 코멘트를 추가해 체크 전환을 직접 확인할 수 있게 했다. 학생 파일과 개인 문서는 포함하지 않았다.
- 자동 테스트 26개와 TypeScript·Vite 빌드가 통과했다. Chrome에서 예제 비교 → 해제·전체 복원 → 다시 제외 → 변경점 이동을 확인했다. 2048px·1280px 화면에서 UI 겹침과 페이지 가로 넘침이 없고, 콘솔 오류·경고가 없었다.

## Decisions

- 적용 범위는 Before만으로 한정했다. After에 코멘트가 남은 경우 전체 비교를 선택할 수 있다.
- 첫 번째 기준 문장까지 포함해 제거하며, 이후의 추가 괄호 안내는 추측해서 지우지 않는다. 실제 열린 예외 파일처럼 문장 뒤 안내가 더 있으면 그 안내는 남는다.
- 비교 결과에서만 무시하면 화면의 긴 코멘트가 그대로 남으므로 렌더링 전에 메모리 사본을 처리했다. 원본 색상·강조 서식은 그대로 유지한다.
- UI 글자는 기존 15px, 보조 안내는 14px로 유지하고 좁은 화면의 도구 모음은 줄바꿈한다. 문서 100% 배율에서 문서 내부 가로 스크롤은 유지한다.
