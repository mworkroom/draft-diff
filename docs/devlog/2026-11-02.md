## Decisions

- 서버 업로드 없이 브라우저 메모리에서 처리한다. 예제 파일만 같은 호스트에서 가져오며 실제 문서와 파일 이름은 전송하지 않는다.
- 사용 목적에 맞춰 기본 배율은 100%, UI 본문과 조작부는 15~16 px, 보조 안내는 14 px로 설정했다. 좁은 문서 패널은 자체 스크롤을 허용한다.
- 머리글·바닥글·각주·미주는 보이지만 본문 비교에서 제외한다. 자동 페이지 번호 반복으로 생기는 거짓 차이를 피하기 위한 결정이며 UI와 README에 범위를 명시했다.
- Word와 브라우저의 조판·글꼴 차이까지 동일하게 만드는 것은 첫 버전 목표가 아니다. 원래 글자 서식 보존과 내용 변경 확인에 집중했다.
- 렌더러의 투명한 페이지 배경을 흰색으로 수정하고, Shadow DOM에서는 적용되지 않는 :root 글꼴 테마 변수를 :host로 변환했다. 첫 이전 버튼의 순환 위치와 변경 표시 해제 시 선택 윤곽선도 수정했다.

## Current Status

Chrome 기본 뷰포트 약 1746×943, 2048×1100, 1280×900, 390×844에서 예제 비교 화면을 확인했다. 원래 빨강·파랑 글씨와 노랑 형광펜 유지, 좌우 비교 배경, 표시 전환, 이전/다음 변경 이동과 순환, 200% 확대 및 100% 복귀, 양쪽 비례 스크롤 연결, UI 글꼴 크기, 페이지 전체 가로 넘침 없음, 관련 콘솔 오류 없음을 확인했다. 1280 px에서는 문서 자체를 가로로 스크롤하며 조작부는 화면 안에 유지된다. 좁은 화면에서 개인정보 안내 문장의 끝부분만 줄바꿈되던 문제도 수정했다.
- 비교 화면 디자인은 흰 헤더·파일 영역·도구 모음·회색 캔버스·좌우 흰 문서로 구성했다. 이미지 생성 참고안과 최종 Chrome 스크린샷을 view_image로 직접 비교했다. 확인 항목은 문구·좌우 배치·서체와 크기·흰색/회색/빨강/파랑 팔레트·버튼/아이콘·간격이다. 페이지가 투명하게 보이던 문제를 수정했다. 원본 문서 서식이 우선이므로 참고안의 문서 배율·내용·강조 글자색은 고정하지 않고 원래 Word 서식을 유지했다. 실제 비교 상태와 범위 안내 문구는 동작 확인을 위해 추가했다. 최종 미리보기 JPEG는 1672×942, 참고안은 1672×941로 비슷한 원본 크기에서 비교했다.
- 초기 npm 설치는 격리 환경 DNS 제한으로 실패하여 승인된 네트워크 실행으로 완료했다. 처음 사용한 happy-dom의 XML 네임스페이스 지원이 DOCX 검증에 부적합해 jsdom으로 교체했고 테스트를 통과했다. DOM 테스트는 레이아웃 검증을 대신하지 않는다.
- Chrome 자동 파일 주입은 확장 프로그램의 파일 URL 권한 제한으로 실패했다. 보안 설정은 변경하지 않았다. 실제 Windows 파일창 검증을 시도했으나 도구가 브라우저 URL을 확신하지 못해 Windows Computer Use를 중단했다. 이후 Windows 앱 입력은 중단하고, URL을 확인할 수 있는 브라우저 탭 경로에서 화면·표시 전환·이동·배율 검증만 완료했다. CDP 스크린샷이 한 차례 시간 초과됐으나 화면 크기 복구 후 다시 캡처했다. 임시 뷰포트 설정은 복구했다.
- 실제 파일창 선택·드래그앤드롭 및 실제 J님 문서는 아직 미검증이다. 샘플 파일 처리 경로와 파일 내용 비교는 Chrome 예제 및 실제 DOCX 자동 테스트로 확인했다.
- Git 저장소 생성·스테이징·커밋·원격 업로드·배포는 하지 않았다. 소스·잠금 파일·문서·가상 예제·배포 설정이 포함 대상이며 node_modules·dist·실제 문서는 제외 대상이다.
- 로컬 정적 서버에서 HTML·JS·DOCX 예제·라이선스 응답, HEAD, 경로 이탈 차단, POST 차단을 확인했다. 런타임 의존성 18개의 라이선스 고지를 빌드에 포함했다. 실행용 dist와 소스를 담은 배포 ZIP을 생성·무결성 검사했고 node_modules·빌드 캐시·실제 문서는 제외했다. ZIP의 dist는 로컬 실행 편의를 위한 것으로 Git 업로드 대상이 아니다.
